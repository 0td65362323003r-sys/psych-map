# KURUMIサイト制作で得たナレッジ（次の案件の精度を上げるために）

最終更新：2026年11月12日。KURUMIのサイトを作る中で、うまくいったこと、失敗したこと、毎回同じように下した判断を、次の案件でそのまま使える形に残します。

## 1. 最終ゴールからの逆算

| 段階 | ゴール | 判定のしかた |
|---|---|---|
| 最終 | オーダーの相談が届き、成約する | 問い合わせ件数と成約数（シートの「対応状況」） |
| 公開 | 本番ドメインで公開し、フォームが届く | 本番URLからテスト送信して、シートとメールの両方に届く |
| 品質 | 5観点のレビューで指摘が0件 | 要件・文章・アート・技術・売上の5人の指摘が0件（先方に確認が必要な項目は別の一覧で管理） |
| 素材 | 事実と素材がそろっている | `docs/REQUIREMENTS.md` に出典つきで書かれている |

## 2. 過去の成果物から分かったこと

### うまくいったこと（再現する）
- **一問一答のヒアリングフォーム（GAS）**：答えるたびにシートへ保存されるので、途中でやめても回答が残る。38問すべての回答が集まった。
- **答えを受け取ってから作る**：要件がそろってから作った部分は、手戻りがほぼなかった。
- **要件を1ファイルにまとめる（REQUIREMENTS.md）**：レビュー担当が「事実かどうか」をこのファイルで判断できるようになった。
- **観点を分けた複数人レビュー**：1回目で105件の指摘が出た。1人で見ていたら見落としていたものが多い（フォームの送信失敗を「送信完了」と表示していた不具合など）。
- **公開前の確認ページを作るスクリプト（scripts/build-preview.sh）**：手作業をやめたら、作り直しの手間がほぼなくなった。

### 失敗したこと（繰り返さない）
| 失敗 | 原因 | 今後のルール |
|---|---|---|
| 質問の回答が来る前に作り始めて止められた | 「早く進めたほうがいい」と思い込んだ | 入力がそろうまでは、流れや設計書を作るまでにとどめる |
| LINEで送る文章を2つに分けて、コピーしにくくした | 受け取る人の操作を考えていなかった | 送る文章は、1回でコピーできる1つのまとまりで渡す |
| AIが書いたような文章になった（「〜を纏う」「紡ぐ」「唯一無二」など） | 決まり文句で埋めた | 下の「AIっぽい表現チェック」を通してから出す |
| テンプレートのような見た目になった | 決まった型から始めた | frontend-design の手順で、大胆にする場所を1か所だけ決める |
| 送信に失敗しても「ありがとう」と表示していた | `no-cors` で送り、結果を見ていなかった | 送信結果（`{"ok":true}`）を確かめてから完了を表示する |
| ヒアリングで聞いた事実をレビュー担当が「根拠なし」と判断した | 打ち合わせの内容が要件ファイルに入っていなかった | 打ち合わせ・ヒアリング・LINEで聞いた事実は、すべて出典つきで要件に書く |
| 「今どこ？」と聞かれて状況説明から始めた | 相手が欲しいものを考えていなかった | 確認用URLを最初に出す |

### 毎回同じように下している判断（判断基準）
1. **事実**：要件ファイルにない事実は書かない。分からないことは仮置きにして「先方に確認」の一覧に入れる。
2. **費用**：商用で使える無料枠を選ぶ（Vercel Hobby は商用不可なので Cloudflare Pages を使う）。規約は一次情報で確かめる。
3. **言葉**：中学生でも分かる言葉で書く。英語は直訳せず、自然な英語にする（固有名詞は残す）。
4. **見た目**：大胆にする場所は1か所（KURUMIでは「生地の見本帳」）。それ以外は余白と書体で整える。
5. **売上**：どのページの終わりにも、次にすること（オーダーの相談）を置く。価格・納期・返信までの日数は隠さない。
6. **ユーザーの手間**：相手の手間が増える提案はしない。次にやることが明らかなら、聞かずにやる。

### 今回のレビューの記録
| 回 | 指摘の数 | 主な中身 |
|---|---|---|
| 1回目 | 105件 | 送信失敗でも「ありがとう」を出す不具合、左右の余白の崩れ、h1がない、価格が作品ページにない、AIっぽい文章 |
| 2回目 | 37件 | 英語の選択肢で送信が失敗する（文字数の上限）、スマホでメニューがはみ出す、英語の経歴に日本語が残る |
| 3回目 | 8件 | 種類が未確認の作品に「ドレス」と表示、同じ案内の重複、代替テキストの二重読み上げ |
| 4回目 | 3件 | 絞り込みに未確認の種類が残る、一覧がスマホで横にはみ出す、最後の行に1文字だけ残る |
| 最終 | 0件 | 5人とも指摘なし（先方に確認が必要な項目は別の一覧で管理） |

学び：
- **直した箇所が新しい不具合を生む**（ヘッダーにボタンを足したらメニューがはみ出した、カードを足したら一覧がはみ出した）。見た目を変えたら、320・360・390・1440pxの全ページで横はみ出しを機械的に確かめる
- **「仮」の情報は1か所隠しても別の場所に残る**（価格を隠しても、種類の表示・絞り込み・フォームの初期選択に残っていた）。未確定の項目は、データに印（`quote`）を付けて、使っている場所をすべて検索する
- **文字数の上限は、英語の選択肢で必ず試す**（日本語より長い）
- レビュー担当には「前回からの差分だけ」を見てもらうと、回を追うごとに速く終わる
- **確認用ページを更新するときは、トップだけでなく全ページのHTMLを送る**（トップだけ送ったため、下層ページが古いまま先方の画面に出た）

## 3. ボトルネック（売上・工数・品質）

| 観点 | ボトルネック | 影響 | 打ち手 |
|---|---|---|---|
| 売上 | 本番公開に必要なアカウント（Cloudflare・ドメイン・Apps Script のデプロイ）がまだない | 公開できないので、問い合わせが0件のまま | 公開手順を1枚にまとめ、先方と30分の画面共有で一度に済ませる |
| 売上 | 作品名・生地・説明が仮のまま | 作品ページで高額品の理由が伝わりにくい | LINE【11】の回答をもらい、作品ごとの説明を入れる（最優先） |
| 工数 | 文章とデザインの作り直し（AIっぽい文章、テンプレートのような見た目） | 2〜3往復分の手戻り | 書く前にチェックリストを通す。デザインは最初に方針を1つ決める |
| 工数 | 確認用ページの公開が手作業だった | 毎回10分ほどかかり、間違いも起きた | スクリプト化した（済み） |
| 品質 | 先方の回答待ちの項目（プロフィール写真・ロゴ・配色・キャッチコピー） | 仮置きのまま公開すると印象が弱くなる | 「先方に確認」一覧として送り、期限を決めてもらう |
| 品質 | レビューを最後にまとめて行った | 105件が一度に出て、直す量が多くなった | 主要ページができた時点で、早めに1回レビューする |

いちばん大きいボトルネックは**公開できていないこと**（売上が0のまま）です。品質を上げる作業より、公開に必要な先方の作業を先に終わらせるほうが、売上に効きます。

## 4. ルール化・Skills化の提案

| 名前 | 中身 | 形 |
|---|---|---|
| hearing-form | 質問一覧から、一問一答のGASフォームとスプレッドシートを作る | Skill（`gas/kurumi-hearing` を雛形にする） |
| requirements-from-hearing | 議事録・回答・LINEから REQUIREMENTS.md を出典つきで作る | Skill |
| ai-tell-check | 下の「AIっぽい表現チェック」で文章を確かめる | Skill（またはCLAUDE.mdのルール） |
| five-lens-review | 要件・文章・アート・技術・売上の5人に並行でレビューさせ、指摘が0件になるまで繰り返す | Workflow / Skill |
| preview-publish | ビルドして確認用ページ（claude.ai）を作り直す | スクリプト（済み）→ Skill にする |
| client-site-launch | ドメイン取得、Cloudflare Pages、GASのデプロイ、テスト送信までの手順 | チェックリスト |

CLAUDE.md に入れておくルール：
- 入力がそろうまでは作り始めない（流れと設計まで）
- 送る文章は1つのまとまりで渡す
- 「今どこ？」には確認用URLから答える
- 事実は REQUIREMENTS.md にあるものだけを使う
- 次にやることが明らかなら聞かずにやる。相手の手間を増やさない

## 5. 見た目を変えたあとの機械チェック（毎回やる）
- 全ページ×（320／360／390／1440px）×（日本語／英語）で `scrollWidth - clientWidth` が0か
- h1が1つか、リンク切れがないか、axe-coreで違反がないか
- 送信フォームは、日本語・英語のすべての選択肢の組み合わせで受け口（GAS）が `ok:true` を返すか

## 6. AIっぽい表現チェック（文章を出す前に通す）
- 使わない言葉：纏う／紡ぐ／織りなす／唯一無二／至高／極上／息づく／〜の世界へようこそ／〜を体験してください
- 「AではなくB」「〜だけでなく〜も」が続いていないか
- 3つ並べる言い方（「美しさ、品格、そして自信」）が続いていないか
- 体言止めが続いていないか
- 本人が実際に言ったことを使っているか（KURUMIでは、ラジオのファンの言葉や「和のものは言葉が分からなくても伝わる」）
- 英語：Elevate / Timeless / Curated / Unparalleled / Embark を使っていないか

## 7. 次の案件で最初にやること
1. 打ち合わせの議事録から REQUIREMENTS.md を作る
2. 足りない事実を一問一答のフォームで聞く
3. 回答がそろったら設計書を作り、デザインの方針（大胆にする場所1か所）を決める
4. 主要ページができた時点で、5観点のレビューを1回行う
5. 公開に必要なアカウントの準備を、作り始めと同時に先方へ頼む
